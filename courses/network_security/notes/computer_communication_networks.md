# I. Exponential and Poisson (指數分佈與卜瓦松過程)

## 1. 本章學習目標與核心概念

在深入探討網路效能之前，我們必須先掌握描述網路中隨機事件的數學工具。本章節介紹的指數分佈與卜瓦松過程，並非抽象的數學理論，而是模擬網路行為的基石。它們被用來建立封包到達、服務處理時間等關鍵隨機事件的模型，是後續分析網路延遲、壅塞與封包遺失等核心效能指標的基礎。

### 1.1 指數分佈 (Exponential Distribution)

指數分佈是一種連續機率分佈，專門用來描述在卜瓦松過程中，兩次連續隨機事件之間的時間間隔。

- **主要應用：** 在網路分析中，它被廣泛用於模擬以下兩種時間：
    - **到達間隔時間 (Inter-arrival time):** 兩個連續封包到達路由器的時間間隔。
    - **服務時間 (Service time):** 路由器或伺服器處理一個封包或請求所需的時間。
- **機率密度函數 (PDF):** 其數學形式為： $f(t) = \lambda e^{-\lambda t}$，其中 $t \ge 0$
- **速率參數 (Rate Parameter):** 公式中的 $\lambda $ 稱為速率參數，代表在單位時間內，事件發生的平均次數。因此，平均事件間隔時間為  $1/\lambda$。例如，若 $\lambda = 5$  packets/sec，則平均封包到達間隔時間為 1/5 = 0.2 秒。

### 1.2 記憶性 (Memoryless Property)

指數分佈最獨特且最重要的特性是「記憶性」。

- **定義：** 如果一個隨機變數 `X` 服從指數分佈，那麼在已知 `X` 大於某個值 `s` 的條件下，`X` 還要大於 `s+t` 的機率，與從一開始 `X` 就大於 `t` 的機率是完全相同的。
- **數學公式：** $P(X > s+t | X > s) = P(X > t)$
- **核心意涵：** 這個特性意味著「過去的等待時間不影響未來的等待機率」。可以把它想像成一個壽命是指數分佈的設備，它不會「老化」。無論它已經運作了多久，它未來還能繼續運作一段時間的機率，和一個全新的設備是一樣的。在網路中，這代表一個封包已經等待的時間，並不影響它還需要等待多久的機率分佈。

### 1.3 卜瓦松過程 (Poisson Process)

卜瓦松過程是用於模擬一系列離散隨機事件發生的模型。在該模型中，我們只知道事件發生的平均速率，但無法預測任何單一事件發生的確切時間點。

- **與指數分佈的關聯：** 兩者關係密不可分。一個卜瓦松過程中，任意兩次連續事件的 **到達間隔時間 (inter-arrival time)**，必然服從 **指數分佈**。
- **關鍵特性：** 在一個固定的時間區間內，事件發生的次數服從卜瓦松分佈。

### 1.4 多個指數過程的整合 (Combining Multiple Processes)

在真實網路中，流量往往來自多個獨立的來源，因此理解如何整合這些隨機過程至關重要。

1. **最小到達時間 (Minimum of Exponentials):**
    - **概念：** 考慮多個獨立的、速率分別為 $\lambda_1, \lambda_2, ..., \lambda_n$的指數過程。其中任何一個過程最先發生事件的時間，也是一個服從指數分佈的隨機變數。
    - **新速率：** 這個新的指數分佈，其速率是所有獨立過程速率的總和，即 $\lambda_{total} = \sum \lambda_i$。
    - **應用：** 這個模型非常適用於分析一個路由器佇列 (queue) 的情況，該佇列接收來自多個獨立來源的封包。
2. **疊加 (Superposition):**
    - **概念：** 將多個獨立的卜瓦松過程合併成一個單一的過程。
    - **結果：** 合併後的新過程仍然是一個卜瓦松過程，其速率等於所有原始過程速率的總和。
3. **稀疏化 (Thinning):**
    - **概念：** 假設有一個速率為 $\lambda_{original}$ 的卜瓦松過程。如果我們以機率 $p$ 獨立地選擇該過程中的每一次事件，而被選中的事件將構成一個新的過程。
    - **結果：** 這個由被選中事件組成的新過程，仍然是一個卜瓦松過程，其新速率為 $\lambda_{new} = p \cdot \lambda_{original}$。

### 🔗 概念連結

指數分佈與卜瓦松過程不僅是理論模型，它們是理解網路核心效能指標的數學基礎。透過這些工具，我們可以對網路中的封包流進行建模，例如 HTTP 請求或 VoIP 通話的「連線到達 (connection arrivals)」，進而分析佇列延遲 (queuing delay) 和封包遺失 (packet loss) 的機率，這些都是在「網路架構」章節中將深入探討的關鍵性能指標。

### 💡 考試提示

- **必考定義：** 指數分佈的 PDF、卜瓦松過程的定義，以及兩者之間的關係（卜瓦松過程的事件間隔時間是指數分佈）。
- **核心特性：** 深刻理解並能解釋「記憶性 (Memoryless Property)」的意涵與公式。
- **整合應用：** 掌握疊加 (Superposition) 與稀疏化 (Thinning) 的概念與計算，並理解如何計算多個指數過程的最小到達時間分佈之新速率 (rate)。

# II. Architecture (網路架構)

## 1. 本章學習目標與核心概念

本章節將解構通訊網路的基礎設計原則。我們將從傳統電話網路的「電路交換」哲學開始，對比當今網際網路核心的「封包交換」模式。接著，我們將深入探討構成現代網路的關鍵組件、衡量其表現的核心效能指標，以及管理複雜性的「分層」結構，這些共同構成了現代資料通訊的基石。

### 1.1 傳統電話網路 (Telephone Network - Tanenbaum)

1. **拓樸結構 (Topology):** 傳統電話網路的拓樸從最初理論上的「完全連接 (fully-connected)」演進為可擴展的「多層級分層結構 (multi-level hierarchical)」。這種分層結構是實現大規模網路擴展的必要手段，它透過集中本地流量、再透過少量長途線路連接不同區域，避免了為每對用戶都建立一條直連線路的高昂成本與複雜性，從而實現了可擴展性 (scalability)。
2. **關鍵組件定義 (Key Components):**
    - **LATA (Local Access and Transport Area):** 本地接取與傳輸區域，是美國電話網路中的一個地理區域概念。
    - **LEC (Local Exchange Carrier):** 本地交換電信公司，負責 LATA 區域內的本地通話服務。
    - **IXC (Interexchange Carrier):** 長途電信公司，負責連接**不同 LATA 之間**的長途通話，是跨區域通訊的橋樑。
    - **POP (Point of Presence):** 接入點，是 IXC 為了讓用戶能夠接入其長途網路而設立的實體設施。
3. **線路與多工 (Lines, Trunks, and Multiplexing):**
    - **線路區分:** `本地迴路 (local loop line)` 指的是從用戶端到交換機的線路，通常是低容量的銅線；而 `中繼線 (trunk)` 是指連接交換機之間的高容量線路，通常使用光纖。
    - **多工目的:** 在昂貴的中繼線上使用多工技術，可以讓成千上萬通電話同時共享一條線路，大幅提升資源利用效率。

|   |   |
|---|---|
|多工技術|運作原理|
|**分頻多工 (FDM)**|將傳輸媒介的頻寬切割成多個不重疊的頻帶，每個頻帶分配給一個獨立的通話。|
|**分時多工 (TDM)**|將時間切割成極小的時間片段 (time slots)，輪流將每個通話的數位化樣本放入這些片段中進行傳輸。|

### 1.2 電路交換 vs. 封包交換 (Circuit Switching vs. Packet Switching)

1. **電路交換 (Circuit Switching):**
    - **核心原理：** 在通訊開始前，必須先建立一條專屬的、端到端的實體電路。該電路在整個通話期間都會被佔用，直到通話結束才釋放。
    - **主要特性：** 同步 (synchronous)、連接導向 (connection-oriented)，且一旦連線建立，通訊品質可靠。
    - **資源分配：** 資源在通話期間被完全預留，這對於像語音這樣速率固定的流量來說非常高效，但對於突發性 (bursty) 的數據流量則會造成大量資源浪費。
2. **封包交換 (Packet Switching):**
    - **核心原理：** 將原始訊息切割成多個較小的數據包 (packets)。每個封包都包含目的地位址，並在網路中獨立地被路由器轉發，直到抵達目的地。
    - **預設特性 (以 UDP 為例)：** 非同步 (asynchronous)、無連接 (connectionless)、不可靠 (unreliable)。
    - **可靠性機制：** 可以在封包交換的基礎上，透過上層協定（如 TCP）來提供可靠的、面向連接的服務，例如錯誤重傳和流量控制。
3. **綜合比較 (Comparative Analysis):**

|   |   |   |
|---|---|---|
|比較項目|電路交換 (Circuit Switching)|封包交換 (Packet Switching)|
|**資源分配**|專用、預留 (Dedicated Reservation)|共享、隨需分配 (Shared, On-demand)|
|**適用流量類型**|恆定速率流量 (如：傳統語音)|突發性流量 (如：網頁瀏覽、檔案傳輸)|
|**建立延遲**|有，需先建立端到端電路|無，封包可立即發送|
|**每個封包的延遲**|固定且可預測，主要由傳播延遲構成，因無須排隊 (queuing) 而沒有隨機的佇列延遲。|包含佇列延遲，會因網路壅塞而變化|
|**可靠性**|一旦建立連線，非常可靠|基礎建設本身不可靠，可靠性需由上層協定 (TCP) 提供|

### 1.3 現代網際網路架構 (Modern Internet Architecture - Kurose)

1. **接取網路 (Access Networks):** 終端主機 (end hosts) 透過各種接取網路技術連上網際網路，例如：乙太網路 (Ethernet)、數位用戶線路 (DSL)、纜線數據機 (Cable Modems)、以及無線區域網路 (Wi-Fi)。
2. **網路的網路 (Network of Networks):**
    - **分層結構：** 現代網際網路是一個由無數個網路相互連接而成的「網路的網路」。其結構大致可分為：接取 ISP (Access ISPs)、區域 ISP (Regional ISPs)、以及骨幹級的 Tier-1 ISP。
    - **關鍵角色：**
        - `ISP (Internet Service Provider)`: 網路服務供應商，提供用戶連網服務。
        - `IXP (Internet Exchange Point)`: 網路交換中心，是一個讓多個 ISP 能夠在此直接交換流量的實體設施，避免流量需要繞道更高層級的 ISP。
    - **客戶關係：** 在這個階層結構中，較低層級的 ISP 通常是較高層級 ISP 的客戶，需付費才能透過其網路連接到全球網際網路的其他部分。

### 1.4 效能指標 (Performance Metrics)

1. **分析四大指標：**
    - **延遲 (Delay):** 一個封包從源頭到目的地所經過的總延遲，可分解為四個部分：
        - `d_proc` ("節點"處理延遲): 路由器檢查封包標頭、決定轉發路徑所需的時間。
        - `d_queue` (佇列延遲): 封包在路由器緩衝區 (buffer) 中等待被傳輸的時間。這是延遲中最主要且隨機變化的部分，直接受網路壅塞程度影響。
        - `d_trans` (傳輸延遲): 將整個封包的所有位元推送到鏈路上所需的時間。計算方式為：`封包大小 / 鏈路傳輸速率`。
        - `d_prop` (傳播延遲): 一個位元從鏈路的一端傳播到另一端所需的時間。計算方式為：`鏈路長度 / 傳播速度`。
    - **封包遺失 (Packet Loss):** 封包遺失是網路壅塞的極端後果。當封包抵達路由器時，若因壅塞導致其緩衝區 (佇列) 已滿，這個封包就會被丟棄。這與造成佇列延遲 (Queuing Delay) 的是同一個根本原因——需求超過了可用容量。
    - **吞吐量 (Throughput):** 單位時間內成功傳輸的數據量。在一個端到端的路徑中，整體的吞吐量取決於路徑上所有鏈路中傳輸速率最低的那一段，也就是所謂的「瓶頸鏈路 (bottleneck link)」。
    - **效率 (Efficiency):** 成功傳遞到目的地的數據量與所使用的總資源之比率，這是衡量資源共享有效性的指標。
2. **壅塞 (Congestion):** 當網路中的數據需求量超過了其可用容量時，就會發生壅塞。壅塞是導致佇列延遲急劇增加和封包遺失的根本原因。

### 1.5 網路分層 (Layering)

1. **分層的動機 (Motivation):** 網路系統極其複雜，將其功能劃分為多個獨立且有階層關係的「層 (layer)」，是一種重要的設計原則。每一層專注於解決一部分特定的問題，並為其上層提供明確定義的服務，從而有效管理系統的複雜度。
2. **網路堆疊 (Protocol Stacks):**

|                       |                      |
| --------------------- | -------------------- |
| OSI 模型 (7 層)          | 網際網路協定堆疊 (5 層)       |
| 7. 應用層 (Application)  | 5. 應用層 (Application) |
| 6. 表現層 (Presentation) |                      |
| 5. 會話層 (Session)      |                      |
| 4. 傳輸層 (Transport)    | 4. 傳輸層 (Transport)   |
| 3. 網路層 (Network)      | 3. 網路層 (Network)     |
| 2. 資料鏈結層 (Data Link)  | 2. 鏈結層 (Link)        |
| 1. 實體層 (Physical)     | 1. 實體層 (Physical)    |

1. **封裝 (Encapsulation):** 在發送端，數據從應用層向下傳遞。每經過一層，該層的協定會為上層傳來的數據加上自己的標頭 (Header)，這個過程稱為「封裝」。例如，傳輸層為應用層的訊息加上 TCP 標頭，形成區段 (Segment)；網路層再為此區段加上 IP 標頭，形成數據包 (Packet)。在接收端，則進行相反的「解封裝」過程，逐層移除標頭，最終將原始數據還原給應用程式。

### 💡 考試提示

- **核心對比：** 必須能流暢地比較電路交換 (Circuit Switching) 和封包交換 (Packet Switching) 的運作原理、資源分配方式及優缺點。
- **效能指標計算：** 清楚區分並能計算四種延遲，特別是傳輸延遲 (Transmission Delay) 和傳播延遲 (Propagation Delay)。理解吞吐量 (Throughput) 由瓶頸鏈路決定。
- **分層與封裝：** 理解分層設計的動機，並能描述封裝 (Encapsulation) 的過程 (上層資料被下層加上 header)。
- **架構名詞：** 掌握 LATA, LEC, IXC, ISP, IXP 等關鍵縮寫的意義。

# III. Application Layer (應用層)

## 1. 本章學習目標與核心概念

應用層是網路應用程式與底層傳輸服務之間的橋樑，它定義了應用程式如何交換訊息。本章節將探討應用層的兩種主要架構模式（主從式與點對點），分析它們所依賴的傳輸層服務（TCP vs. UDP），並深入了解驅動全球資訊網（HTTP）和電子郵件（SMTP, POP3, IMAP）等關鍵網路服務的具體協定。

### 1.1 應用層架構與服務 (Architectures and Services)

1. **架構模式 (Architectural Paradigms):**

|   |   |   |
|---|---|---|
|架構模式|核心特性|優缺點|
|**主從式 (Client-Server)**|存在一個「永遠在線 (always on)」的伺服器，負責回應來自多個客戶端的請求。客戶端之間不直接通訊。|**優點:** 管理集中、架構簡單。<br>**缺點:** 伺服器易成為效能瓶頸與單點故障，擴展性較差。|
|**點對點 (Peer-to-Peer, P2P)**|每個節點 (peer) 同時扮演客戶端與伺服器的雙重角色。節點之間可以直接通訊與交換資訊。|**優點:** 高度可擴展性、無單點故障。<br>**缺點:** 管理與搜索較為複雜，需要額外機制來尋找擁有目標內容的節點 (peer discovery) 並宣告自身可用性 (content advertisement)。|

1. **傳輸層服務 (Transport Services):** 應用程式可以根據自身需求，選擇以下兩種主要的傳輸層服務之一：
    - **TCP (Transmission Control Protocol):**
        - **可靠的資料傳輸：** 保證數據不遺失、不重複、按順序到達。
        - **流量控制 (Flow Control)：** 防止發送方發送速度過快，壓垮接收方。
        - **壅塞控制 (Congestion Control)：** 當網路發生壅塞時，主動降低發送速率。
        - **連接導向 (Connection-oriented)：** 在傳輸數據前，必須先建立一個邏輯上的連接。
    - **UDP (User Datagram Protocol):**
        - **不可靠的資料傳輸：** 不保證數據是否到達、是否按順序，盡力而為 (best-effort)。
        - **無流量/壅塞控制：** 以最快速度發送數據，不管接收方或網路狀況。
        - **無連接 (Connectionless)：** 無需建立連接即可直接發送數據。

### 1.2 WWW 與 HTTP (HyperText Transfer Protocol)

1. **HTTP 架構:** HTTP 是全球資訊網 (WWW) 的應用層協定，它基於主從式模型運作。瀏覽器作為客戶端 (client)，向網站伺服器 (web server) 發送請求，以獲取網頁、圖片等物件 (objects)。
2. **連線管理 (Connection Management):**
    - **非持續性 HTTP (Non-Persistent HTTP):** 這是早期的運作模式。每請求一個物件（例如，主 HTML 檔案、頁面上的每一張圖片），都需要建立一個全新的 TCP 連線。請求完成後，該連線立即關閉。這種方式的 TCP 連線建立與關閉的開銷 (overhead) 非常大，效率低下。
    - **持續性 HTTP (Persistent HTTP):** 這是現代瀏覽器的預設模式。客戶端與伺服器之間建立一個 TCP 連線後，可以透過這條單一的連線來請求和傳輸多個物件。直到一段時間沒有新的請求後，連線才會被關閉。這大大減少了連線建立的延遲與伺服器負擔。
3. **狀態管理與 Cookies (State Management):**
    - **無狀態協定 (Stateless Protocol):** HTTP 協定本身是「無狀態」的，這意味著伺服器不會記錄任何關於客戶端過去請求的資訊。每一次請求都被視為完全獨立的事件。
    - **Cookies 的作用：** 為了在無狀態的 HTTP 上實現使用者登入、購物車等需要「記憶」的功能，引入了 Cookies 機制。
        - **運作流程：**
            1. 伺服器在回應中包含 `Set-cookie` 標頭，並附帶一個獨一無二的識別碼。
            2. 客戶端的瀏覽器收到後，會將這個 Cookie (識別碼) 儲存起來。
            3. 在後續對該伺服器的所有請求中，瀏覽器都會自動附上這個 Cookie。
            4. 伺服器藉由檢查請求中的 Cookie，就能識別出是哪個用戶，從而維持其登入狀態或購物車內容。

### 1.3 電子郵件 (Email)

1. **整體架構 (Email Architecture):** 電子郵件系統主要由三個部分構成：
    - `用戶代理 (User Agents)`: 使用者用來讀寫郵件的軟體，如 Outlook、Gmail 網頁版。
    - `郵件伺服器 (Mail Servers)`: 負責儲存、轉發郵件的伺服器。
    - `SMTP (Simple Mail Transfer Protocol)`: 郵件傳輸協定。
2. **流程:** 寄件人的用戶代理將郵件發送給寄件方的郵件伺服器，該伺服器使用 SMTP 協定將郵件「推送」到收件方的郵件伺服器，最終收件人再透過用戶代理從其郵件伺服器上讀取郵件。
3. 值得注意的是，電子郵件系統是一個混合式架構。從用戶代理到郵件伺服器的上傳/下載過程是典型的主從式 (Client-Server) 模型；然而，郵件伺服器之間透過 SMTP 協定交換郵件的過程，本質上是一種對等 (Peer-to-Peer，或更精確地說是 Server-to-Server) 的互動模式。
4. **郵件協定 (Mail Protocols):**
    - **SMTP (Simple Mail Transfer Protocol):** 這是一個「推送 (push)」協定。它的主要職責是將郵件從寄件方的郵件伺服器推送到收件方的郵件伺服器。同時，它也用於從寄件人的用戶代理將郵件推送到其郵件伺服器。
    - **郵件存取協定 (Mail Access Protocols):** 當郵件抵達收件方的郵件伺服器後，收件人需要一種協定來將郵件從伺服器上「拉取 (pull)」下來。這就是郵件存取協定的作用。

|   |   |   |
|---|---|---|
|協定|運作模式|適用情境|
|**POP3 (Post Office Protocol)**|通常會將伺服器上的郵件**下載**到本地設備，然後從伺服器上**刪除**。其設計理念類似於傳統郵局，信件領走後郵局就不再保留。|適用於固定在單一設備上收發郵件的用戶。|
|**IMAP (Internet Mail Access Protocol)**|郵件主要**保留在伺服器上**。用戶代理操作的實際上是伺服器上的郵件副本，並允許使用者在伺服器上建立、管理多個資料夾。|適用於需要在多個設備（如電腦、手機、平板）上同步存取郵件的現代用戶。|

1. **與 HTTP 比較 (Comparison with HTTP):** 兩者最根本的區別在於操作模式：SMTP 是一個「推送 (push)」協定，主動將數據從客戶端推向伺服器；而 HTTP 是一個「拉取 (pull)」協定，由客戶端發起請求，從伺服器拉取數據。

### 💡 考試提示

- **架構比較：** 清楚區分主從式 (Client-Server) 與點對點 (Peer-to-Peer) 架構的特點。
- **傳輸服務選擇：** 能夠說明 TCP 與 UDP 的服務差異，並能舉例解釋為何不同應用會選擇其一（例如：為何要求不掉資料的網頁瀏覽 (HTTP) 和電子郵件必須使用 TCP，而能容忍少量封包遺失但對延遲極度敏感的串流影音 (Streaming) 和 VoIP 更適合使用 UDP）。
- **HTTP 核心機制：** 掌握非持續性 (Non-persistent) vs. 持續性 (Persistent) 連線的運作與效率差異。必須理解 HTTP 為何是無狀態 (stateless) 的，以及 Cookies 如何解決此問題。
- **Email 協定分工：** 準確描述 SMTP, POP3, IMAP 在 email 收發流程中各自扮演的角色（誰是 push，誰是 pull）。
